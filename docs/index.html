RegulationR 7.5.ii

76% attendance is not “fine”. It is two marks you have already lost.

Under Regulations 2024, attendance is not only an eligibility gate — it is a scored component of your internal marks, worth up to 5 of them, in every subject, in bands. Full marks start at 85%.

So a student sitting comfortably above the 75% line is still forfeiting marks, in every subject, quietly, all semester. No portal shows this. No other calculator computes it. It is the single largest number most students never see.

And below 60%, the door shuts. R 6.2 lets the Principal condone attendance under 75% only as far as 60%. Below that the exam cannot be sat, and attending from there on does not change it. TargetX says so on the day it becomes true — not after results.

What itdoes

The mark you need, per subject

Both pass conditions, not one: the 40% separate end-semester minimum as well as the combined total. Spreadsheets miss the first, which is how a subject that “looked passed” comes back as a supplementary.

How many classes you can still miss

Computed from real attended-over-held counts, with duty leave credited the way R 6.3.ii actually caps it — at 10% of classes held, which grows as you spend it. Answered as a number of classes, not a percentage.

The cheapest route to your CGPA

Name a target. TargetX works backwards to the SGPA each remaining semester has to carry, then to which subject is cheapest to push and how far — balanced so the plan is one a person can actually attempt, rather than four subjects at 95.

Your marks, in without typing them

Sign in to your college’s etlab portal and it pulls every semester, attendance, series marks, grades and published SGPA in one pass. Your password is used for that one request and never stored — or skip it entirely and type things in by hand.

Rather than ask you to take that on trust, every release publishes SHA256SUMS-<platform>.txt beside the installers, so you can check that what you downloaded is what was built. A checksum proves the file did not change in transit, not who built it — it is not a substitute, and this page will say so until one is bought.
Updates come to you. The app checks for a new version a few seconds after it opens and offers it; you accept or decline. Update payloads are signed, and a build only installs one signed by the key compiled into it — an unsigned or wrongly signed update is refused rather than installed.

Where yourdata lives

On your machine. That is the whole answer.

There is no account, no sign-up and no server belonging to us. Your marks are a file in your own user profile. Nothing about them is transmitted anywhere, and there is no telemetry, no analytics and no crash reporting — the app makes network requests to exactly three places:

github.com
Once on launch, to ask whether a newer version exists. Block it and the app works unchanged.
raw.githubusercontent.com
Once on launch, to refresh the KTU course catalogue, so a curriculum revision does not need a new build.
Your college portal
Only when you press Sync, and only to the address you typed. Your password is held for the length of that one request — never written to disk, never put into the saved record, never in the export, never in a log.
Sync has been proved against one college’s etlab so far. If yours lays its pages out differently, the sync fails and shows you what it could not read rather than recording half a semester. You can check whether it will work without giving anyone an account: save your academics page from a browser you are already signed in to, and drop the file onto Data → “Will sync work at my college?”. The page never leaves your machine; what the app offers you to send is a separate block of table shapes with every digit blanked out.

Install scope
Per user, not per machine — no administrator rights, and a student’s academic record stays out of a shared location on a lab machine.
Silent deployment
NSIS /S and msiexec /qn, for Intune, SCCM or a login script.
Reads only
The app has no code path that writes to a portal. The session cookie lives in the native process, where nothing in the web layer can reach it.
